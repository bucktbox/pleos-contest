## 1. 총평

**3단계 루프(P단 적재 → 주행 → P단 개봉)와 '깨지기 쉬운 화물' 스토리, 피칭 문장은 v4.5 보다 좋다. 그대로 살린다.**
문제는 그 위에 얹은 약속들이다. 검증되지 않은 판정(차선 변경·1.5초·부드러운 제동), DO "100% 방어" 단정, 실제처럼 보이는 포인트·쿠폰·제휴, 개인 점수 TOP10, 보험사 스폰서, 근거 없는 MAU·리텐션, 그리고 이 약속들을 받칠 **서버 작업이 WBS 에 없음**. 심사위원(현대차그룹 실무진)은 연출보다 이 공백을 먼저 볼 가능성이 크다.

## 3. 지적 사항 (심각도순, Claude 확인 결과 포함)

### 높음
1. **블루링크와의 비교가 빠짐** (타당) — Q1 이 티맵·캐시워크만 상대한다. 심사위원 첫 질문은 "우리 블루링크 안전운전 점수와 뭐가 다르냐"일 것. 게다가 BM 도식에 **보험사(UBI) 스폰서**, 결과 화면에 **"무결점 98점 TOP10"** 이 있어 오히려 겹침을 키운다.
   → 보험사 제거, 개인 점수 랭킹 제거. "평가가 아니라 배송 이야기, 보험과 무관" 포지셔닝 (v4.5 6.2 문장 재사용).
2. **주행 중 게임 요소 = 주행 안전 지침 위반 소지** (타당, 지침 원문 확인) — "Zero-UI"라 해도 게이지·콤보음·효과음은 '게임 유도'로 읽힐 수 있다. "DO 메타데이터 + Foreground Service 로 100% 방어"는 확인 안 된 단정.
   → 주행 중엔 화면·소리 없이 신호만 기록, 모든 연출은 P단. "정책 적합성은 주최 측 확인 중"으로 표기.
3. **'차선 변경'·'0.1초 단위'·'1.5초' 확정 표현** (타당) — 조향각과 깜빡이만으로 차선 변경을 판정할 수 없다(커브·주차·회피와 섞임). 콜백 주기·지연은 미측정.
   → "깜빡이와 큰 조향의 순서"로 한정, 1.5초는 '시연용 가설값'.
4. **벌점 설계의 안전 문제** (타당) — "브레이크를 나눠 밟으면 보상"은 필요한 제동을 미루는 유인이 될 수 있다. "깜빡이 안 켜면 상자가 깨져 안 열림"도 출퇴근길에 불필요한 조작을 유도할 수 있다.
   → **가점만 있고 벌점은 없는 구조**: 깜빡이를 먼저 켜면 보너스, 놓치거나 판정이 애매하면 불이익 없음. 급제동은 보상과 연결하지 않음. *(v4.5 의 "급제동 → 화물 흔들림"도 같이 고쳐야 함)*
5. **실제처럼 보이는 포인트·쿠폰·제휴** (타당) — 현대Shop·블루멤버스·Pleos 포인트 전환, "500 Pleos 포인트", 카페 쿠폰이 기능과 시연에 실제처럼 나온다. 제휴 근거가 없고, 여러 사업자에서 쓰는 포인트는 **선불전자지급수단(전자금융거래법) 검토 대상**이 될 수 있다(추정, 확인 필요).
   → 1차 제출본은 **가상 보상**("시연용, 실제 사용 불가" 자막). 제휴·포인트 전환은 ⑥ 확장 계획으로만.
6. **위치·개인정보 흐름이 없음** (타당) — 내비 목적지 → 스폰서 매칭 → 도착 확인 → 건당 과금 → "스폰서에게 방문객 데이터 제공"은 개인위치정보 제3자 제공(위치정보법 제19조 동의·통보) 문제. 좌표를 안 보내도 "누가 언제 어느 매장에 도착"은 위치를 드러낸다.
   → 1차 범위: 도착 판정은 기기 안에서만, 서버·스폰서로 전송 안 함. 데이터 흐름도 1장 추가.
7. **서버 작업이 WBS 에 없음** (타당) — TOP10 랭킹·스폰서 매칭·QR 쿠폰·도착 과금·포인트 원장은 전부 서버가 필요한데 WBS 는 "Mock JSON·로컬 랭킹"뿐. v4.5 의 11/05 기준선도 사라졌다.

### 중간
8. **MAU·리텐션 수치** (타당) — 50만 대·설치 40%·활성 75%·W1 72%·W4 55%·DAU/MAU 60% 모두 근거 없음. 초기 MAU 30% → 2028년 60% 로 비율이 바뀌는 설명도 없음. Codex 계산 예: 500P=500원·DAU 9만·1일 1회면 **월 포인트 재원 13.5억 원**(조건부 계산).
   → 산식 `호환 차량 수 × 사용자 환산 × 도달률 × 설치율 × 권한 동의율 × 월 의미 행동률` 을 보수/기준/낙관 3안으로, 각 값에 출처·가정 표시.
9. **BM 내부 충돌** (타당) — 리텐션은 출퇴근(집·회사)에서 나오는데, 스폰서가 돈을 내는 건 '추가 방문'. 이미 가는 집·회사에 매장이 돈을 낼 이유가 약하다.
10. **시연 시나리오가 Console 에서 안 되는 장면 포함** — 골드 조명, 벨트 버프 (위 2절).
11. **권한 표기** (타당) — 벨트는 `getSeat()` 아래라 `CAR_SAFETY` 근거 없음. FusedLocation 은 `pleos.car.permission.FUSED_LOCATION`(dangerous) — "위치/오디오"로는 부족.
12. **테일싱크와 상위 구조 겹침** (타당) — "주행 데이터 → 이야기 → 도착 피날레". 아이 대상 오디오 동화와는 다르지만, 차이를 한 문장으로 준비해야 함.
13. **조명 원복** — 색만 백업하고 밝기도 바꾼다. 밝기 백업·재출발·앱 종료 시 원복 규칙 필요.

### 낮음
14. "100%·완벽·절대·압도적" 표현, "스마트폰은 절대 모른다"(관성센서로 일부 추정 가능), 캐시워크를 'GPS 거리 앱'으로 묶음(실제는 걸음 수), 경쟁안 폄하("카풀 5% 미만" 근거 없음).
15. "3D 언박싱"과 Lottie(2D) 혼용.

## 4. v4.5 와 v4.7 — 팀이 정할 것

v4.7 은 v4.5 에서 뺀 것 일부를 근거 없이 되살렸다(개인 점수 TOP10, 행정동 여부 불명, 보험사 UBI, 주행 중 GPS 속도, 고정 리텐션 목표). 반대로 v4.5 의 서버 기준선·축소 기준은 사라졌다.

**Claude 제안 — v4.8 은 두 판을 합친다**
- v4.7 에서 가져올 것: 3단계 루프, 위트 있는 카고 예시, 피칭 문장, 접수양식 ①~⑥ 원고 틀, 스폰서 카고 BM(단 확장 계획으로)
- v4.5 에서 가져올 것: 겹침 판정표, 위치 원칙(기기 안에서만), 서버 3종(크루·직접 고른 동네·시즌 — 점수가 아니라 배송 거리 합산), 11/05 기준선
- 새로 바꿀 것: 주행 중 무음·무화면 수집, 가점만 있는 규칙, 1차는 가상 보상, MAU 시나리오 산식, Console 가능 범위에 맞춘 시연

## 5. 제출 전 Top 5 (Codex 제안 문구, Claude 동의)

1. **판정 범위 한정**: "방향지시등과 조향의 발생 순서를 가상 화물 규칙에 쓴다. 차선 변경·법규 준수·사고 위험은 판정하지 않는다. 1.5초는 시연용 가설값. 신호 누락·판단 불확실 상황에 불이익 없음. 급제동·급조향을 보상 상실 조건으로 쓰지 않는다."
2. **DO 단정 제거**: "주행 중에는 게이지·애니메이션·콤보 음성을 표시하지 않고 허용 범위의 신호 수집만 한다. 정차 화면은 기어와 `CarUxRestrictions` 를 함께 확인한다. 주행 중 수집 허용 여부는 주최 측 확인 사항."
3. **보상 분리**: "1차 제출본의 보상은 현금 가치가 없는 가상 아이템이며 쿠폰·랭킹 화면은 시연용 데이터. 현대Shop·블루멤버스·Pleos 결제·보험사 연계는 미확정 제휴 제안."
4. **범위·일정**: "1차 구현은 카고, 차량 신호 수집, 로컬 규칙, 정차 결과·도감. 개인 점수 공개 랭킹·스폰서 자동 매칭·실쿠폰·포인트 정산 제외. 11/01 필수 SDK·권한·주행 제한 POC, 11/05 기능 동결."
5. **숫자를 가설로**: MAU 산식 시나리오화, W1·W4·DAU/MAU 고정 목표 삭제, 초기 실험 지표(결과 화면 재방문, 보상 없는 반복 이용, 사용자당 보상 원가)로 대체.
