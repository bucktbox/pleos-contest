* **AR 표현 삭제** (v4.7) — 이번 제출 범위에서 카메라 기반 AR 은 제외. 'P단 트렁크 카고 개봉 연출'로 표현.

## PART 2. 피칭 & 예상 질문

### 2.1 오프닝 피칭 (v4.7 수정)

> **"심사위원님, 출퇴근길을 매일 달리면서, 내 운전이 기억에 남는 날이 있으신가요?"**
>
> 운전을 바꾸려는 서비스는 대부분 **점수를 매깁니다.** 그런데 점수는 평가받는 느낌이고, 보상은 1년 뒤 보험료입니다.
>
> 만약 오늘 출근길, 내 차 트렁크에 **'한 방울도 흘리면 안 되는 순두부 젤라또'** 를 하나 싣고 간다면 어떨까요?
> 운전 중에는 아무것도 보지 않아도 됩니다. 차가 기억합니다 — 방향을 틀기 전에 깜빡이를 먼저 켰는지, 누구와 함께 탔는지.
> 그리고 목적지에 도착해 **기어를 `P`에 넣는 순간**, 오늘 화물을 얼마나 고이 모셨는지가 열리고 실내 조명이 그 등급의 색으로 바뀝니다.
>
> 점수 대신 이야기로 남는 운전 — 스마트폰 단독으로는 얻기 어려운 차량 신호로 만드는 배송 앱, **『세이프 카고』** 입니다.

### 2.2 예상 질문 4가지

* **Q1. "블루링크에도 안전운전 점수가 있습니다. 왜 이 앱이 필요합니까?"**
  * **A1**: 블루링크는 지난 운전을 **평가**해 보험 혜택으로 연결합니다. 세이프 카고는 평가하지 않습니다. 점수·순위·보험이 없고, 오늘 운전을 **배송 이야기와 수집**으로 남깁니다. 재료도 다릅니다 — 블루링크 점수가 쓰지 않는 **방향지시등과 조향의 순서, 동승자 착석·벨트**를 씁니다. 그래서 두 서비스는 경쟁이 아니라 공존합니다.
* **Q2. "운전 중 게임이면 위험하지 않습니까?"**
  * **A2**: 주행 중에는 **화면 연출도, 효과음도 없습니다.** 앱은 허용된 범위에서 차량 신호만 기록합니다. 모든 결과와 연출은 기어가 `P`이고 플랫폼의 주행 제한 상태(`CarUxRestrictions`)가 풀렸을 때만 열립니다. 규칙도 **가점만** 있습니다 — 깜빡이를 놓치거나 급제동을 해도 화물을 잃지 않습니다. 필요한 제동을 망설이게 만드는 규칙은 두지 않았습니다. *(주행 중 수집 허용 범위는 주최 측 확인 중)*
* **Q3. "깜빡이를 먼저 켰는지 정확히 판정할 수 있습니까?"**
  * **A3**: 우리가 보는 것은 **'핸들을 크게 돌리기 전에 깜빡이가 켜져 있었는가'** 라는 순서뿐입니다. 차선 변경이나 법규 위반은 판정하지 않습니다. 순서 판정의 기준 시간(현재 1.5초)은 시연용 가설값이고, 콜백 지연을 측정해 조정합니다. 판정이 애매하면 불이익 없이 넘어갑니다.
* **Q4. "보상 재원은 어디서 나옵니까?"**
  * **A4**: 1차 제출본의 보상은 가상 아이템(카고 도감·도장·크루 기여)입니다. 상용화 단계에서는 지자체 관광 캠페인과 로컬 매장이 **'목적지 스폰서 카고'** 를 거는 모델을 검토합니다. 이는 제휴·정산 계약과 위치정보·개인정보·전자금융 관련 검토를 마친 범위에서만 도입합니다 (⑥).

## PART 3. 공식 접수양식(DOCX) ①~⑥ 원고

### ① 앱 한 줄 소개
> **"깨지기 쉬운 화물을 싣고 달리는 배송 앱 — 운전 중엔 차가 조용히 기억하고, 목적지에서 `P`를 넣는 순간 오늘의 운전이 화물 이야기로 열린다."**

### ② 기획 배경

#### 1. 지금의 운전 서비스는 '평가'에 머문다
* 모바일·커넥티드 운전 점수는 급가속·급감속 같은 사건을 세어 **점수와 보험 할인**으로 연결합니다. 운전자에게는 평가받는 경험이고, 보상은 멀고 추상적입니다.
* 그리고 도로에서 체감하는 매너 — **방향을 틀기 전 깜빡이를 먼저 켜는 습관, 동승자 모두가 벨트를 맸는지** — 는 이런 점수에 잘 드러나지 않습니다.

#### 2. Why Pleos Connect
* Pleos `Vehicle SDK` 는 방향지시등 상태(`TurnSignal`), 조향각(`SteeringWheel`), 기어(`Gear`), 좌석별 착석과 벨트(`Seat`)를 콜백으로 제공합니다. 스마트폰 단독으로는 직접 얻기 어려운 신호입니다.
* 기어 `P` 라는 명확한 '도착' 순간이 있어, 주행 중에는 아무것도 보여주지 않고 정차 후에만 경험을 여는 **안전한 구조**를 만들 수 있습니다.

### ③ 주요 기능 및 차량 특화 요소 (3단계 루프)

**[Step 1. 적재 — P단] → [Step 2. 주행 — 화면·소리 없음] → [Step 3. 개봉 — P단]**

#### Step 1. 적재 (출발 전, 기어 P)
* 오늘의 카고 1개가 트렁크에 실립니다.
  * **일상 배송**(기본): 출퇴근용. 목적지 없이, 일정 거리 이상 달린 뒤 P 에 넣으면 도착.
  * **목적지 배송**(조건부 ⚠️): 순정 내비 목적지를 읽을 수 있으면(`NaviHelper`, 0.3 질문 4) 목적지 성격에 맞는 카고. 못 읽으면 앱에서 장소를 고름.
* 위트 있는 카고 예시 (v4.7):
  * 강릉 여행길 — **"한 방울도 흘리면 안 되는 순두부 젤라또"**
  * 휴게소 경유 — **"바삭함이 생명인 알감자 타워"**
  * 평일 출근길 — **"결재 도장이 흔들리면 안 되는 부장님의 결재판"**
* 동승 확인: 착석 **+** 벨트 체결된 좌석 수만큼 **동승 파티**. 신호를 지원하지 않는 좌석은 계산에서 빼고 불이익 없음.

#### Step 2. 주행 (기어 P 가 아닐 때)
* **화면 연출·효과음 없음.** 앱은 허용된 범위에서 신호만 기록합니다 (주행 안전 지침 준수 설계, 허용 범위는 ⚠️ 확인 중).
* 기록하는 것 — **가점만**:
  1. **깜빡이 먼저** (`TurnSignal` + `SteeringWheel`): 핸들을 **크게** 돌리기 전에 같은 방향 깜빡이가 켜져 있었으면 보너스. 차선 변경처럼 작은 조향은 보지 않음. 놓쳐도 감점 없음.
  2. **동승 파티 유지** (`Seat`): 출발 때의 파티가 도착까지 유지되면 보너스.
  3. **무사 도착** (`Odometer` 트립 거리 + `Gear`): 배송 거리 기록.
* 보지 않는 것: 급제동·부드러운 제동, 조향 변화율, 속도. (차속 API 가 없고, 제동을 보상과 묶으면 필요한 제동을 망설이게 할 수 있음)

#### Step 3. 개봉 (도착, 기어 P)
* 기어 `P` + 주행 제한 해제 확인 → 카고 개봉 연출(Lottie) → **결과 카드**: 카고 등급(보너스 수로 결정), 깜빡이 먼저 횟수, 동승 파티, 배송 거리.
* **앰비언트 조명**: 등급 색으로 3초 점등 후 원복 (`setAmbientLightBrightnessColor`·`setAmbientLightBrightness`, 색·밝기 모두 백업). 권한 미승인 시 화면 테두리 연출.
* **쌓이는 것**(기기 저장): 카고 도감, 지역 도장판, 연속 배송 기록.
* **함께 모으는 것**(서버, 1.4): 크루 주간 합계, 동네 대항전, 시즌 공동 의뢰 진행률.

* 모든 리스너 `unregister*` / `release()` 해제, 조명은 앱 종료·재출발 시에도 원복.

### ⑥ 기대효과 및 발전 가능성

#### 1. 타깃
* **필수 신호(기어·깜빡이·조향)가 지원되는 국내 Pleos Connect 차량 운전자.** 착석·벨트·조명은 지원 차량에서만 켜지는 선택 기능.
  * 주 5일 출퇴근 운전자 — 일상 배송, 크루
  * 주말 가족 나들이 — 동승 파티, 목적지 배송, 지역 도장

#### 2. 예상 MAU — 시나리오 산식 (💡 수치는 PM 이 출처와 함께 기입)

> **MAU = 호환 차량 수 × 사용자 환산 계수 × 앱 도달률 × 설치율 × 권한 동의율 × 월 의미 행동률**

| 입력 | 보수 | 기준 | 낙관 | 근거 구분 |
| :--- | :---: | :---: | :---: | :--- |
| 국내 호환 차량 수 (기준 시점 명시) | | | | 외부 근거 (공식 판매·보급 자료) |
| 사용자 환산 계수 (차량 1대당 운전자) | | | | 외부 근거 / 가정 |
| 앱 도달률 (스토어 노출) | | | | 가정 |
| 설치율 | | | | 가정 |
| 권한 동의율 | | | | 가정 |
| 월 의미 행동률 (결과 화면 1회 이상 확인) | | | | 가정 |

* '의미 행동' = 자동 실행이 아니라 **사용자가 결과 화면을 연 경우**로 정의.
* 리텐션 목표치는 실측 전이므로 기재하지 않고, **초기 실험에서 측정할 지표**로 제시: 결과 화면 재방문율, 보상 없이 반복 이용하는 비율, 크루 참여율, (상용화 시) 사용자당 보상 원가.

#### 3. 확장 계획 — 목적지 스폰서 카고 (💡 가설)
* **로컬 매장·휴게소**: "우리 매장에 도착해 P 를 넣으면 열리는 카고"를 후원 → 방문 유도. 단 **도착 ≠ 구매**이므로 쿠폰 사용 확인으로 효과를 측정.
* **지자체 관광·교통안전 캠페인**: 숨은 명소·전통시장 방문 카고, 캠페인 기간 한정 시즌 의뢰.
* **현대차그룹 생태계**: 획득 혜택을 현대Shop·블루멤버스·Pleos 앱마켓과 연결하는 제휴 **제안**.
* 도입 조건: 제휴·정산 계약 + **위치정보법**(개인별 방문 정보 제3자 제공 시 동의·통보, 사업자 신고 여부) + **개인정보 보호법** + **전자금융거래법**(여러 사업자에서 쓰는 포인트의 선불전자지급수단 해당 여부) 검토 완료 후.
* 💡 재원 규모 예시(조건부 계산, Codex): 사용자당 1일 500원 × 일 활성 9만 명 × 30일 = **월 13.5억 원**. 출퇴근(집·회사) 배송에는 스폰서가 돈을 낼 이유가 약하므로, 스폰서 재원은 **추가 방문(주말·여행)** 에 한정해 설계.
