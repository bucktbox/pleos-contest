**SleepGuard Pro의 통합안은 과합니다. 지금은 ‘입구핀’, ‘우리차 셔틀’, ‘SleepGuard 축소판’을 독립 후보로 검증하는 게 낫습니다.** `report.md`는 읽기만 했으며 수정하지 않았습니다.

평가는 공식 4항목을 따르되, 점수는 제 판단입니다. **공식 배점은 비공개**입니다. [공식 심사 기준](https://appdevchallenge.auto-hmg.io/guide/judging-awards)

**1. SleepGuard Pro 비평 — 10줄 이내**

- **차량특화성:** 하이패스 음량·조명·공조를 함께 조절하는 가치는 강하다. 다만 SDK 도메인 개수가 많다고 가치가 커지지는 않는다.
- **창의성:** ‘아이 잠든 순간’은 명확하지만, 멀미·병원 검색·추억 캡슐까지 붙이면서 앱의 정체성이 흐려졌다.
- **기술활용성:** 앞에서 미확인으로 표시한 터널·곡률·소아과 API와 Gleo를 최종 아키텍처에서 다시 핵심처럼 사용한다.
- **기술 정확성:** 브레이크 페달 상태는 급제동 강도가 아니며, **주차브레이크는 변속기 P단이 아니다**. 창문 개방률을 곧바로 ‘2cm’로 보장할 수도 없다.
- **사업성:** 영유아 동반 가구의 문제는 선명하지만, 사용 빈도·다운로드 이유·순정 기능 대비 우위 검증이 부족하다.
- **효과 검증:** 수면 감지 없이 ‘숙면 시간’, 가속도 없이 ‘평온 주행 점수’를 확정적으로 보여주면 신뢰를 잃는다.
- **범위 판단:** 개발자 1명이 3주 동안 예측 제어·음성·다중 제어·오디오·아카이브를 완성한다는 계획은 낙관적이다.
- **축소안:** **사용자가 수면 모드 시작 → 지원되는 하이패스 음량·조명 조절 → 종료 시 이전 설정 복구.** 이것부터 출시 가치가 있는지 확인하자.

**2. 새 아이디어 6개**

공통 전제부터 명확히 하겠습니다.

- 아래는 **외부 API·Gleo·카메라 없이**, 공식 5종 SDK 중 필요한 것과 로컬 저장·규칙만 사용하는 구상입니다. 5종을 전부 사용할 필요는 없습니다. [공식 개발 환경](https://appdevchallenge.auto-hmg.io/guide/development)
- ‘전 차종 공통’은 **가솔린·하이브리드·EV에서 같은 문제를 해결한다는 뜻**입니다. 개별 장비 지원과 권한은 별도이며, 조회·제어 모두 지원 여부와 승인 범위를 확인해야 합니다. [Vehicle 문서](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/Vehicle/intro), [권한 정책](https://document.pleos.ai/en/api-reference/connect-sdk-pleos)
- 설정·수정·긴 확인은 주차 후, 주행 중에는 필요한 짧은 안내만 제공합니다. **백그라운드 지속 실행과 주행 제한 연동은 출시 전 검증 사항**입니다.
- 아래 이용 빈도와 3주 구현 가능성은 **가설·개발 추정**입니다. 데모 범위는 각 항목에 적은 한 가지 흐름으로 제한합니다.

**A. 입구핀 — “건물 주소 말고, 지난번 제대로 들어간 그 입구로.”**

- **누구·언제:** 매주 방문하는 병원·학원·대형 아파트에서 정문과 주차장 입구를 반복해서 헷갈리는 운전자.
- **핵심·SDK:** 주차 후 현재 위치를 ‘실제 입구’로 확인 저장하고, 다음 방문 출발 전에 순정 내비로 바로 전달. `FusedLocation`, `NaviHelper`, `Vehicle: Door`, `STT/TTS`. 문 열림은 저장 제안의 단서이며 입구 판정은 사용자가 한다.
- **왜 차인가:** 스마트폰 단독으로는 **순정 내비 목적지·차량 도어 이벤트·실제 도착 좌표를 연결한 저장과 재안내**를 같은 흐름으로 처리하기 어렵다.
- **리텐션:** 주 2회 이상 반복 방문 → 한 번 수정한 입구 재사용 → 개인 입구 목록 축적.
- **3주 데모 킬러:** 잘못된 건물 핀 대신 저장한 주차장 입구 좌표를 선택하자 **주소 재입력 없이 순정 내비 목적지가 바뀐다**. 에뮬레이터 위치 이동과 Console 도어 이벤트로 저장 흐름도 시연.
- **리스크:** 모바일 지도 즐겨찾기와 중복. **좌표를 줘도 내비가 다른 도로로 보정할 수 있어 실제 입구 안내는 선행 검증 필수**이며, 지하 층수·차선 안내는 제외.

**B. 챙겨 — “차에서 내리는 순간, 오늘 가져가야 할 것만.”**

- **누구·언제:** 출근할 때 노트북, 귀가할 때 도시락통, 운동 후 장비를 차에 두고 내리는 사람.
- **핵심·SDK:** 주차 중 “회사에서는 노트북”처럼 장소별 물건 등록 → 해당 장소 도착 후 운전석 문을 열면 미완료 항목만 안내. `Vehicle: Door`, `FusedLocation`, `STT/TTS`.
- **왜 차인가:** 스마트폰 위치 알림만으로는 **운전자가 실제로 차에서 내리려고 문을 연 순간**에 맞춰 알려줄 수 없다.
- **리텐션:** 주 5일 출퇴근·주 2회 운동 → 반복 체크리스트 자동 재활성화 → 완료·보류로 알림 조정.
- **3주 데모 킬러:** 회사 좌표에서는 조용하다가 Console에서 운전석 문을 열자 **“노트북 챙기세요”**; 완료한 항목은 다시 말하지 않는다.
- **리스크:** 현대차의 도어 이력 기반 후석 알림과 상당 부분 겹친다. **장소·물건별 기억**이 차별점이며, 물건 존재나 실제 수거를 감지한다고 주장하면 안 된다. [현대차 후석 알림 설명](https://ownersmanual.hyundai.com/full_webhelp/CN7/2025/en_GN/idd474054285c.html)

**C. 잠깐모드 — “지금만 바꾸고, 원래 내 차로 돌려줘.”**

- **누구·언제:** 동승자가 추워하거나 잠깐 기다리느라 설정을 바꾼 뒤, 기존 설정을 기억하지 못하는 운전자.
- **핵심·SDK:** 앱에서 임시 공조·조명 설정 적용 전 값을 저장 → 주차 후 종료하면 복구. 세션 중 사용자가 다시 바꾼 항목은 자동 복구에서 제외. `Vehicle: HVAC·Light`, `STT/TTS`.
- **왜 차인가:** 스마트폰 단독으로는 **차량의 현재 설정을 읽고, 임시 변경과 이후 변경을 구분해 되돌릴 수 없다.**
- **리텐션:** 주 1회 이상 동승·대기하는 사람 → 임시 변경 → 원복 → 자주 쓰는 임시 설정 재사용.
- **3주 데모 킬러:** 두 설정을 임시 변경하고 Console에서 온도를 다시 수정 → 종료 시 **조명만 복구하고 수정한 온도는 보존**.
- **리스크:** 순정 프로필·설정 복구와 중복이 크다. 테슬라도 프로필 저장·복구를 제공한다. **임시 변경의 수명 관리**가 차별점이지만 단독 앱 구매력은 약하다. [테슬라 프로필](https://www.tesla.com/ownersmanual/model3/en_us/GUID-A2D0403E-3DAC-4695-A4E6-DC875F4DEDC3.html)

**D. 우리차 셔틀 — “매주 같은 픽업, 다음 목적지까지 한 번에.”**

- **누구·언제:** 학교→학원→배우자 직장→집처럼 매주 여러 사람을 태우는 가족 운전자.
- **핵심·SDK:** 현재 위치에서 저장한 정차 지점들을 요일별 순서로 등록 → 도착·문 열림 후 주차 상태에서 “탑승 완료” 확인 → 다음 목적지 전달. `NaviHelper`, `FusedLocation`, `Vehicle: Door`, `STT/TTS`.
- **왜 차인가:** 스마트폰 단독으로는 **차량 승하차 이벤트와 순정 내비의 다음 목적지를 직접 이어 처리하기 어렵다.**
- **리텐션:** 주 2~5회 고정 픽업 → 오늘 순서 재사용 → 결석·순서 변경만 수정.
- **3주 데모 킬러:** Console에서 뒷문을 열고 닫아도 즉시 출발 처리하지 않다가, **“탑승 완료” 확인 후 다음 학원으로 안내가 이어진다.**
- **리스크:** 다중 경유지 내비·셔틀 관리 앱과 중복. 자동 배차·타인 위치·탑승자 식별은 제외한다. Claude ②와 달리 **보급 장소 발견이 아닌 반복 승하차 작업의 진행 관리**가 핵심이다.

**E. 딱좋아 — “에어컨 숫자 대신, ‘지금 추워’를 기억하는 공조.”**

- **누구·언제:** 같은 출근길에서도 냉방을 켰다 껐다 반복하며 매번 온도를 조정하는 사람.
- **핵심·SDK:** 주차 중 선택한 사용자별로 “춥다/덥다/딱 좋다”와 당시 실내외 온도·설정을 저장 → 다음 유사 조건에 선호 설정 제안. `Vehicle: HVAC`, `STT/TTS`. 초기에는 자동 적용 대신 주차 중 확인.
- **왜 차인가:** 스마트폰 단독으로는 **실제 공조 상태·실내 온도·사용자의 설정 수정 결과를 함께 읽고 적용할 수 없다.**
- **리텐션:** 주 5일 출퇴근 → 짧은 피드백 → 다음 탑승의 설정 제안 개선. 학습은 단순 조건표로 시작.
- **3주 데모 킬러:** 서로 다른 외기 조건을 Console로 입력하면, 같은 사용자에게 **서로 다른 저장 선호값**을 제안한다.
- **리스크:** 순정 AUTO·개인화 공조와 중복이 가장 크다. 시연은 가능하지만 실제 쾌적성 개선은 실차 검증이 필요하다. **추천받는 것 자체가 귀찮을 가능성**도 있다.

**F. 바통 — “차를 넘길 때, 설명도 같이 넘긴다.”**

- **누구·언제:** 한 차를 번갈아 쓰며 “주차 B2 C구역, 세차카드는 콘솔” 같은 설명을 매번 보내는 가족.
- **핵심·SDK:** 주차 후 음성 인계 메모와 주행거리 저장 → 다음 사용자가 차량에서 프로필을 선택하면 인계 사항 표시·읽기. `Vehicle: Door·Odometer`, `STT/TTS`. 동일 차량 내 로컬 저장.
- **왜 차인가:** 스마트폰 메신저만으로는 **그 차의 다음 이용 시작과 인계 메모 확인을 자동으로 연결할 수 없다.**
- **리텐션:** 주 2회 이상 차량 교대 → 남기기 → 다음 사람이 확인 → 미완료 인계만 유지.
- **3주 데모 킬러:** 사용자 A가 메모를 남기고 세션 종료 → Console 도어 이벤트 뒤 사용자 B 선택 → **이번 인계 메모와 이전 이용 이후 주행거리** 표시.
- **리스크:** 가족 메신저·공유차 서비스와 중복하며 공유 가구로 시장이 좁다. 자동 신원 인식·원격 전송·실내 주차 위치 측정은 제공하지 않는다.

**3. Claude 후보 평가 — 각 3줄**

**① P단 전용 게임**  
매력: 세 후보 중 스토어에서 눌러보고 싶은 첫인상은 가장 강하다.  
약점: 테슬라 Arcade와 경쟁하며, 확인된 조향각·P단 신호 없이 핸들 게임을 약속할 수 없다. 실제 창문·조명 효과도 반복 이용 가치는 별도다. [테슬라 Arcade](https://www.tesla.com/ownersmanual/model3/en_kr/GUID-79A49D40-A028-435B-A7F6-8E48846AB9E9.html)  
판정: **게임 자체의 재미와 확실한 주차 제한을 먼저 입증해야 하는 고위험 후보.** 도메인 연동 시연만으로는 부족하다.

**② 알아서 들르기**  
매력: 사용자에게서 직접 나온 불편을 해결하며, 전 동력원으로 확장하기도 좋다.  
약점: 최저가·실시간 빈 충전기 데이터는 5종 SDK만으로 확보된다고 볼 수 없고, 자동 경유지 변경은 거부감을 줄 수 있다.  
판정: **외부 데이터 허용 시 유력 후보.** 현재 조건에서는 저장한 보급 장소 추천까지만 가능해 원안의 매력이 줄어든다.

**③ 드라이브 랩드**  
매력: 구현·시각화·공유 시연이 쉽고 전 차종에 적용하기 좋다.  
약점: 운전 점수·차계부·이동 기록과 차별성이 약하며, 카드 한 번 보고 다음 달에도 앱을 열 이유가 부족하다.  
판정: **독립 출시 앱으로는 후순위.** 비교적 쉬운 제작 난도가 다운로드 욕구를 대신하지 못한다.
