## 1. 한 줄 정의

차 안의 공기·빛·바람·소리를 한 번에 바꾸는 **"분위기 레시피"** 를 저장하고 꺼내 쓰는 Pleos Connect 앱. 버튼 하나(또는 음성 한 마디)로 차량 하드웨어 여러 개가 동시에 그 분위기로 바뀐다.

## 2. 왜 만드는가

### 출발점
- PM 은 마스터리포트 #14 데자-드라이브(그날의 온도·조명·바람 복원)에서 **"복원"** 에 가장 끌렸다. [결정]
- 개발자(아이오닉6 오너)의 실제 니즈: "자율주행이 있으면 쉬고 싶다", "시동 켠 채 앉아 있는 시간 = 누구 기다릴 때 / 충전할 때", "퇴근길". [결정]

### 데자-드라이브에서 바꾼 것과 이유
데자-드라이브 원안은 위치·시간·동승자 대화 녹음을 "그날의 기억"으로 저장하고, 같은 장소에 가면 자동 재생했다. 개발자가 **사생활 사고**를 지적했다 — 차는 여러 사람이 함께 타는 공간이라, 과거 동승 기록이 다른 동승자 앞에서 재생되면 심각한 문제가 된다. 녹음은 통신비밀보호법·위치정보법 이슈도 있다(법률 자문 아님, 추정).

→ **"기억(누구·어디·언제)"은 버리고 "분위기"만 남긴다.** 복원의 매력은 살리고, 기록 위험은 구조적으로 없앤다. [결정]

### 왜 스마트폰이 아니라 차인가
폰은 차 안의 온도·빛·창문·시트를 바꿀 수 없다. 레시피 하나로 차량 하드웨어 5~6개를 동시에 움직이고, 끄면 원래대로 되돌리는 것은 Vehicle SDK 로만 가능하다.

## 3. 목표 / 비목표 / 반목표

**목표**
- Pleos 스토어에서 "받아보고 싶다"는 첫인상을 주는 출시형 앱 (공모전 데모 전용 아님). [결정]
- 가솔린·하이브리드·EV **전 차종**에서 쓸 수 있다. [결정]
- 매일 다시 여는 이유(리텐션)가 있다 — 퇴근길·기다리는 시간. [결정]
- 개발자 1명이 ~11/12 까지 에뮬레이터에서 동작하는 APK + 시연 영상을 만들 수 있는 범위.

**비목표 (첫 버전에서 안 함)**
- 레시피 공유·둘러보기·커뮤니티 — 서버가 필요해 후속 확장으로 미룸. 기획서에는 확장 계획으로 적는다. [결정]
- 음악 스트리밍 앱 연동.
- Gleo(LLM 음성 비서) 연동 — 공식 SDK 5종 밖, 승인 필요. 기획서에 확장 기능으로만 적는다.
- 외부 공공 API.

**반목표 (기술적으로 돌아가도 이러면 실패)**
- 위치·동선·동승자·대화를 **기록**하는 것. 위치 기반 **자동 재생**. 녹음. → 어떤 형태로도 넣지 않는다. [결정]
- 운전 중 화면 조작을 요구하는 것.
- 사용자 동의 없이 차량 설정을 바꾸는 것 (제안은 하되 자동 적용하지 않는다). [Claude 판단]
- 끈 뒤에 차량이 레시피 상태로 남아 있는 것 (복원 실패).

## 4. 사용자와 순간

| 순간 | 트리거 (위치 사용 안 함) | 앱의 행동 |
|---|---|---|
| **퇴근길** (매일, 전 차종) | 사용자가 정한 시간대 + 기어 P→D | "퇴근길이네요. '퇴근 디톡스' 틀까요?" 1회 제안. 탭하면 적용, 무시하면 사라짐 |
| **기다리는 시간** (충전·픽업 대기, 전 차종) | 기어 P 상태 N분 이상 유지 | "기다리는 동안 '라운지' 어때요?" 1회 제안 |
| **아무 때나** | 사용자가 앱을 열거나 STT 로 "라운지 틀어줘" | 레시피 목록에서 원터치 적용 |

- 트리거는 **시간 + 기어 상태만** 쓴다. "퇴근"은 회사 위치가 아니라 사용자가 정한 시간대로 판단 → "기록하지 않는다" 약속 유지. [Claude 판단 — 사생활 원칙에서 도출]
- 제안 쿨다운: 같은 트리거는 하루 1회, 거절 시 그날 다시 안 띄움. N 기본값 3분. [Claude 판단]

| 바람 세기·방향 | `setHvacFanSpeed`, `setHvacFanDirection` | |
| 내/외기 | `setHvacRecirculation` | |
| 앰비언트 조명 색·밝기 | `setAmbientLightBrightnessColor`, `setAmbientLightSwitch` | **트림별 미지원 가능** → capability 확인 후 생략 |
| 창문 열림 정도 | `setWindowPosition` | 주행 중 제약 (6장) |
| 시트 열선·통풍 | `setHvacSeatTemperature`, `setHvacSeatVentilation` | |

### 적용 범위 — 동승자 유무로 결정 [결정]
- **조수석(또는 다른 좌석)에 누가 앉아 있으면 "차 안의 분위기"**: 공조(듀얼이면 전 영역)·앰비언트·사운드는 차 전체, 시트 열선·통풍은 **사람이 앉은 좌석에만** 적용.
- **혼자면 "나만의 분위기"**: 운전석 영역·운전석 시트만. 듀얼 공조는 운전석 쪽만.
- 착석 판정: `getCurrentSeatOccupancy` / `registerSeatOccupancy` (SDK 실측 확인). 착석 감지를 지원하지 않는 차는 **운전석만**으로 동작. [Claude 판단]
- 창문 개방과 시트 위치 이동은 동승자 유무와 관계없이 **운전석만**. 동승자 자리의 창문·자세를 운전자 레시피가 바꾸지 않는다. [Claude 판단]
- 적용 중에 동승자가 타거나 내리면 범위를 다시 계산할지: 기본은 **적용 시점 기준 유지**(재계산 안 함). [Claude 판단]
- 레시피 자체는 범위를 저장하지 않는다 — 같은 레시피가 상황에 따라 다르게 적용된다. 스냅샷은 실제 적용한 영역만 저장한다.

- 각 요소는 `check…Capabilities` 로 지원 여부를 확인하고, 미지원 요소는 조용히 건너뛴다. 레시피 카드에 "이 차에서 적용되는 항목"을 표시. [Claude 판단]
- 레시피에는 **이름·아이콘·색 + 위 값들만** 저장한다. 생성 시각·위치·사용 이력은 저장하지 않는다(사용 횟수 통계 정도는 로컬에만 둘지 builder 재량, 단 위치는 절대 금지).

### 기본 레시피 (첫 실행 시 제공) [Claude 판단 — 디자이너가 다듬음]
퇴근 디톡스 / 라운지 / 비 오는 밤 / 바다 드라이브 / 첫눈 / 집중(졸음 방지). 5~6개. 깔자마자 바로 써볼 수 있어야 한다.

### 레시피 만들기
- **지금 차 상태를 담기**: P단에서 "지금 분위기 저장" → 현재 차량 값들을 읽어 레시피로 저장. ← 데자-드라이브 "복원" 감성의 직접 계승.
- **편집**: P단에서만 각 값을 조정.

## 6. 동작 규칙

### 적용 / 끄기 (복원)
1. 적용 직전 해당 요소들의 **현재 값을 스냅샷**한다.
2. 레시피 값들을 적용한다 (요소별 비동기 IPC, 실패한 요소는 표시만 하고 나머지는 진행).
3. 끄면 스냅샷으로 되돌린다.
4. **적용 중 사용자가 직접 바꾼 요소는 되돌리지 않는다** (사용자 의도 우선 — Codex '잠깐모드' 제안에서 가져옴). 이를 위해 적용 후 해당 요소 콜백을 구독해 앱 외 변경을 감지. [Claude 판단]
5. 레시피는 한 번에 하나만 활성. 다른 레시피로 바꾸면 최초 스냅샷은 유지한다. [Claude 판단]
6. 시동 OFF/앱 종료 시 처리: [미확인 — builder 가 Pleos 앱 수명주기 확인 후 결정. 기본안: 시동 OFF 시 복원하지 않고 종료(다음 시동 때 차량 기본 동작에 맡김)]

### 안전 (Zero-Distraction)
- 운전 중(기어 ≠ P): **저장된 레시피 원터치 적용/끄기, STT 음성 명령만** 허용. 만들기·편집은 P단에서만.
- 운전 중 레시피 적용 시 **창문 개방은 적용하지 않음**, 시트 등받이 이동도 적용하지 않음. [Claude 판단]
- 제안 카드는 큰 터치 타깃 1개 + 닫기, 일정 시간 후 자동 사라짐.
- 기어 상태: `getCurrentGearSelectionState` / `registerGearSelection`.

### 음성
- STT SDK 로 "○○ 틀어줘", "꺼줘" 정도의 고정 명령. TTS 로 짧은 확인 응답. [Claude 판단]
- Gleo 연동은 기획서에 확장 기능(App Schema 예시)으로만.

## 8. 기술 [Claude 판단]

- Kotlin + Jetpack Compose, 단일 Activity. 로컬 저장 Room(또는 DataStore). 서버 없음.
- Pleos SDK: Vehicle 2.3.2 (`ai.pleos.playground:Vehicle:2.3.2`, repo `https://nexus-playground.pleos.ai/repository/maven-releases/`), SpeechToText, TextToSpeech. NaviHelper·FusedLocation 은 쓰지 않음(위치 미사용 원칙).
- 참고 구현: `github.com/Pleos-Playground/pleos-sample-vehicle-app` (Vehicle 세션·capability·listener 처리 패턴).
- 개발 환경: Android Studio + Pleos Connect Emulator(AVD), JDK 17, SDK 35.
- 제출: GitHub 저장소(소스 + `apk/팀명_앱이름_release.apk` + README), 시연 영상.

### 차량 접근 계층과 시연 방식 [Claude 판단 — builder 검토 반영]
- 앱은 Vehicle SDK 를 직접 부르지 않고 `VehicleGateway` 인터페이스 뒤에 둔다. 구현 2개: **실제 SDK 구현** / **Fake 구현**(메모리 상태 + 앱 외 변경을 흉내 내는 디버그 패널).
- 에뮬레이터에서 set 후 값이 실제로 바뀌지 않는 경우(R1) 대비: 시연·검증은 **SDK 호출 로그 + 앱 내 차량 상태 패널**로 증명한다. 스냅샷·복원·"사용자 변경 보존" 로직은 Fake 구현으로 단위 테스트한다.
- 콜백(`register…`)이 없는 요소(예: 팬 방향)는 적용 중 주기적 재조회로 앱 외 변경을 감지한다.

### 백그라운드 제약 시 대안 [Claude 판단]
- 기어 콜백 상시 구독이 허용되지 않으면(R7): 제안은 **앱이 떠 있을 때만** 동작하고, 리텐션 근거는 "퇴근길 STT 한 마디"와 "지금 분위기 저장" 습관으로 서술한다. 시동 시 자동 실행·위젯 허용 여부는 설명회 확인 후 추가.

## 9. 성공 기준

- 에뮬레이터에서: 기본 레시피 적용 → 지원 요소 값 변경 확인 → 끄기 → 원래 값 복원, 앱 외 변경 요소는 유지.
- P→D 전환 + 지정 시간대에서 퇴근 제안 1회, P 유지 N분에서 라운지 제안 1회.
- 운전 중 편집 화면 진입 불가, 창문·시트는 적용 안 됨.
- 위치 권한을 요청하지 않는다.
- 조수석 착석 상태를 바꾸면 같은 레시피가 "나만" ↔ "차 안 전체" 범위로 다르게 적용된다.
- 제어 퍼미션이 없는 환경에서도 Fake 구현으로 전체 시나리오를 시연할 수 있다.
- 1차 서류 접수양식 ③④⑤⑥ 항목을 이 설계로 채울 수 있다.
