# 세이프 카고 화면정의서 v1.0 전달 메모

2026-10-31 · PM

화면정의서 v1.0(HTML 파일 첨부)을 앱 개발자와 디자이너에게 전달합니다. GitHub 업로드는 저장소 권한이 정리되는 대로 올립니다. 2026-11-01 POC 리뷰 전에 읽고, 아래 체크리스트 항목에 답을 가져와 주세요.

## 먼저 볼 것

**앱은 Pleos Connect 디스플레이 6종, 앱 창 12개에서 모두 동작해야 합니다.** 화면정의서 02장의 반응형 규칙(RL-01~10)이 모든 화면에 적용되므로 02장을 가장 먼저 읽어 주세요.

| 장 | 내용 | 누가 꼭 볼지 |
| --- | --- | --- |
| 01 | Pleos 디스플레이 6종 해상도 · 앱 창 크기 · Window Policy | 둘 다 |
| 02 | 창 크기 등급 6개(L/P × 낮음·보통·높음) · 반응형 규칙 RL-01~10 | 둘 다 |
| 03 | 상태 전이와 화면 흐름 — 화면 전환은 차량 상태가 정한다 | 개발자 |
| 05 | 화면 보완 제안 SD-01~09 (PM 승인 전) | 둘 다 |
| 06 | 화면 상세 CM-01 · SC-00~08 (가로 · 세로 와이어프레임 + 등급별 배치 표) | 둘 다 |
| 07 | 미결 · 확인 Q-01~06 · 12개 창 점검표 | 둘 다 |

- 창 크기 등급의 경계는 **폭 960dp, 높이 900 · 1200dp**입니다. 기준 화면은 S-17 가로 1700×1184dp, 가장 작은 창은 628×800dp입니다.
- 12개 창 중 6개가 높이 900dp 미만입니다. **낮은 창은 예외가 아니라 절반**이라는 전제로 작업해 주세요.
- SD-01~09는 화면을 그리면서 나온 제안이라 PM 승인 전입니다. 승인 전에는 PRD 잠정안 범위에서만 구현해 주세요.

## 앱 개발자 당부

**가장 큰 함정은 브레이크포인트입니다.** Material 기본 WindowSizeClass(폭 600 · 840dp)를 그대로 쓰면 S-17 세로 창(840dp)이 Expanded로 잡혀 세로 화면이 2단으로 깨집니다. 등급은 직접 정의해 주세요.

**반응형**

1. 창 크기 등급은 **폭 960dp(가로/세로), 높이 900 · 1200dp(낮음/보통/높음)** 으로 직접 계산합니다. 디스플레이 이름으로 분기하지 않습니다(RL-02).
2. **화면 방향을 고정하지 않습니다.** `screenOrientation` 지정 금지, 리사이즈 허용. Window Policy상 세로 앱 2개가 떠 있으면 우리 앱도 세로로 시작합니다(RL-08).
3. 크기 단위는 dp · sp만 씁니다. 160 DPI와 200 DPI 기기가 섞여 있습니다(RL-01 · RL-09).
4. 12개 창은 **Compose @Preview 기기 스펙**(`spec:width=840dp,height=1184dp,dpi=160` 형식)으로 등록해 두면 회귀 점검 비용이 가장 적습니다. 창 목록은 화면정의서 07장 점검표에 있습니다.
5. 에뮬레이터에 Connect-W · WF 프로파일이 없을 수 있습니다(Q-04). 이때 화면 크기 강제 변경으로는 시스템 UI 때문에 앱 창 dp가 정확히 맞지 않으므로, 정확한 수치 검증은 Preview로 하고 에뮬레이터는 동작 확인용으로 써 주세요.

**상태 보존 — 실행 중에 창이 바뀝니다**

- 사용자가 윈도 바를 끌면 실행 중에 가로↔세로가 바뀌고, W-Standard는 차량 상태에 따라 W-Extended로 세로가 늘어납니다(Q-05).
- 카고 HP · Key · 버프 · 개봉 단계는 **판정 엔진(서비스)이 들고, 화면은 구독만** 합니다(SD-05). 화면이 다시 만들어져도 값이 그대로여야 합니다.
- 언박싱 Lottie는 창이 바뀌어도 **같은 프레임에서 이어서** 재생해야 합니다. 재생 진행값을 엔진이나 저장 가능한 상태에 둬 주세요.

**주행 화면 · 차량 연동**

- 어느 정차 화면에 있든 주행으로 바뀌면 SC-03으로 자동 이동합니다. 주행 화면에는 버튼이 하나도 없습니다(FR-APP-005).
- 판정 피드백은 **소리가 먼저**입니다. 앱 창이 가려지거나 내비만 보여도 차임 · 효과음 · TTS는 나가야 합니다(RL-10). 주행 중 소리 허용 여부는 U-01 회신을 기다리는 중입니다.
- 앰비언트 조명은 적재 때 현재 색 · 밝기를 저장하고, 개봉 3초 점등 후 **앱 종료 · 창 숨김 경로에서도 반드시 원복**해 주세요. 실패하면 앱 창 테두리 라이트로 대체합니다(FR-VH-011 · 012).
- 위치는 정차할 때 한 번만 읽고 바로 버립니다. 목적지 목록을 **거리순으로 정렬하지 않습니다**(NFR-PRI-001).
- 도착했는데 앱이 화면에 없으면 앱을 앞으로 끌어올리지 말고 TTS로 안내한 뒤 개봉 대기를 유지합니다(SD-06 · Q-02).

## 디자이너 당부

**세로(840×1184dp) 시안을 가로와 동시에 잡아 주세요.** 차량을 타면 내비가 기본 앱으로 뜨기 때문에, 세이프 카고는 내비 옆 세로 창에서 쓰일 가능성이 큽니다(추정).

**기준 캔버스 · 반응형**

1. 기준 프레임은 S-17 **가로 1700×1184dp**와 **세로 840×1184dp** 두 개입니다. 12개 창을 모두 그리지 말고, 컴포넌트를 가로 · 세로 두 변형으로 만들어 주세요.
2. 극단 창은 핵심 3화면(SC-01 로비 · SC-03 호위 · SC-05 언박싱)만 따로 확인합니다. 가장 좁은 창 628×855, 가장 낮은 창 1256×800 · 648×800, 가장 높은 창 1640×1400입니다.
3. 낮은 창에서는 **장식부터 줄입니다** — 히어로 이미지 → 설명 문구 → 여백 순. 카고 · 게이지 · 주 버튼은 줄이지 않습니다(RL-04). 높은 창에서는 핵심 요소를 키우지 않고 여백으로 둡니다(RL-05).
4. Figma는 오토 레이아웃과 최소 · 최대 폭을 설정해서 창을 늘리고 줄여 보며 확인해 주세요. 개발자가 비율을 그대로 옮길 수 있습니다.

**Pleos 디자인 가이드**

- **Status bar · Driving view · GNB는 시스템 UI입니다.** 앱 안에 시계 · 네트워크 · 속도를 다시 그리지 마세요. 앱 창 바로 아래가 GNB라 하단 탭 대신 가로는 좌측 레일, 세로는 상단 세그먼트를 제안했습니다(SD-01).
- 버튼은 Pleos **Basic button**의 Large · Medium · Small 크기와 Pressed · Disabled · Loading 상태를 따릅니다. 주 버튼은 Large입니다.
- Pleos 문서에 버튼 · 터치 치수가 없어 **최소 64×64dp를 잠정값**으로 두었습니다(SD-03 · Q-01). Figma의 Pleos 키트나 실치수를 확인하면 교체해 주세요.
- 색은 Pleos Foundations Colors 토큰을 쓰세요. 라이트 · 다크 테마 제공 여부는 아직 확인하지 못했습니다. 야간 주행을 생각하면 다크 테마도 확인해 주세요.

**주행 화면 · 등급 표현**

- 주행 화면(SC-03)에는 **문장을 두지 않습니다.** 숫자 · 아이콘 · 게이지 · 카고 모양만 씁니다. 카고 상태는 멀쩡함 → 금 → 크게 금 3단계 모양으로, 곁눈질 1초에 읽혀야 합니다(SD-02).
- 등급은 **색 + 이름 + 상자 모양** 세 가지로 함께 표시합니다(SD-07). 잠정 색은 레전더리 Purple · 에픽 Blue · 레어 Cyan입니다(AG-02). 실내 조명 색과 화면 색이 같은 인상인지 함께 봐 주세요.
- 판정 피드백은 소리가 먼저라, 차임 2종(성공 · 퍼펙트 시그널)과 금 가는 효과음 1종도 디자인 범위에 넣어 주세요.

**에셋 · Mock 표기**

- 카고 · 등급 연출은 벡터 Lottie로 만듭니다. 200 DPI 디스플레이에서 비트맵은 흐려집니다(RL-09).
- 스폰서 · 금액 · 제휴명 **바로 옆에 「예시」 배지**를 붙입니다(SD-08). 랭킹 표시명 예시에도 실명을 넣지 마세요(FR-SUB-004 · 익명 규정).
